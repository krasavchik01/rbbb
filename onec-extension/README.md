# HUB ↔ 1С:Бухгалтерия для Казахстана

Исходники расширения `HUB_1C_Exchange` собраны для:

- 1С:Предприятие 8.3.23;
- Бухгалтерия для Казахстана 3.0.73.1;
- серверная база `MAK_290424`.

Расширение только читает бухгалтерские документы и отправляет их исходящим HTTPS-запросом в HUB. Оно не изменяет счета, АВР, ЭСФ, платежи или проводки в 1С. Распроведение, пометка удаления и снятый признак оплаты передаются как отмена ранее импортированной записи.

## Источники

- `Документ.СчетНаОплатуПокупателю` → `invoice`;
- `Документ.РеализацияТоваровУслуг` + связанный `ЭлектронныйАктВыполненныхРабот` → `avr`;
- `Документ.ЭСФ` (исходящие) → `esf`;
- `Документ.ПлатежноеПоручениеВходящее.РасшифровкаПлатежа` → `payment`.

Одна входящая оплата может быть распределена по нескольким договорам. Одинаковые строки
расшифровки агрегируются по устойчивому бизнес-ключу: GUID платежного документа + договор +
контрагент. Номер строки 1С в идентификатор не входит, поэтому сортировка или перестановка
строк не создаёт повторные оплаты в HUB. По каждому такому распределению передаётся своя
сумма, и оплата не приписывается целиком только первому проекту.

## Безопасный порядок запуска

1. Загрузить папку `HUB_1C_Exchange` в существующее отключенное расширение.
2. Выполнить проверку модулей в Конфигураторе.
3. Оставить `HUB_ОбменВключен = Ложь`.
4. Заполнить URL, ключ и дату начала.
5. Выполнить `ПроверитьСвязь()` с пустым пакетом.
6. Нажать **Запустить обмен сейчас** и проверить число подготовленных записей.
7. Только после успешной ручной загрузки включить автоматический обмен.

После перезапуска 1С откройте раздел **HUB** и команду **Настройка обмена с HUB**.
На одной форме задаются адрес API, секретный ключ и дата начала обмена. Кнопка
**Проверить связь** отправляет в HUB пустой тестовый пакет без бухгалтерских документов.
Кнопка **Запустить обмен сейчас** выполняет контролируемую ручную загрузку. При включенной
галочке регламентное задание настраивается автоматически на 08:00, 12:00, 16:00 и 20:00.

## Исправление v5: полный снимок без дублей и ложных удалений

Для установки используйте архив
`HUB_1C_Exchange-v5-full-snapshot-2026-08-21.zip`. Внутри него находится одна корневая
папка `HUB_1C_Exchange` с 18 файлами выгрузки конфигуратора.

Версия v5 включает исправление одиночного запуска из v4 и добавляет безопасную сверку
полного снимка. Установить v5 нужно до следующего контрольного полного обмена.

### Один запуск обмена

В ручном запуске настройки подключения сохраняются без повторной записи регламентного
задания. Это устраняет обнаруженный сценарий, в котором сохранение уже включенного задания
могло одновременно активировать наступивший запуск по расписанию, и один клик отправлял два
одинаковых потока пакетов.

Переключатель автоматического обмена и расписание применяются только кнопкой **Сохранить**.
Проверка связи и ручной запуск сохраняют адрес, ключ и дату начала, но не включают,
не отключают и не переносят регламентное задание.

Полного межпроцессного mutex намеренно нет: надежная блокировка между рабочими
процессами кластера 1С потребовала бы либо отдельного объекта метаданных для lease-lock,
либо перевода ручного запуска в то же фоновое задание с единым ключом и изменения поведения
формы. Проверка списка фоновых заданий перед прямым запуском имеет race condition, а
удержание транзакционной блокировки во время длительных HTTPS-запросов опасно для рабочей
базы. Поэтому расширение содержит безопасный точечный фикс причины фактического двойного запуска,
не меняя расписание и бухгалтерские данные.

Каждый полный ручной или регламентный запуск получает новый `runId`. Все рабочие пакеты
одного запуска передают одинаковый `runId`, последовательный `batchIndex` (начиная с 1)
и общее число пакетов `batchCount`, а также `fullSnapshot = true` и `snapshotSince`,
равную выбранной в форме дате начала. Непосредственно перед чтением документов 1С также
фиксирует единый UTC-момент `snapshotCapturedAt` для всех пакетов запуска. Это позволяет HUB однозначно собрать один запуск,
отличить его от параллельного или повторного обмена и только после получения всех пакетов
снять с учета записи, которые действительно исчезли из полного снимка 1С. Если уже пришел хотя бы один пакет более
нового снимка той же базы либо другой запуск с тем же секундным моментом, неоднозначный
или более старый запуск ничего не удаляет. Пакеты без единого момента снимка импортируются,
но не запускают очистку только до первого версионированного снимка источника; после него
устаревшее расширение получает безопасный результат `upgrade_required` и не может
перезаписать свежие данные. Перед любыми изменениями HUB атомарно резервирует пакет и
берет эксклюзивную блокировку источника в базе данных. Параллельный более новый пакет
получает повторяемую ошибку `source_busy`, а более старый помечается `skipped` до чтения
проектов. Если миграция этой блокировки еще не установлена, HUB отвечает 503 и не меняет
проекты или реестр 1С. Пустая проверка
связи передает `fullSnapshot = false` без полей запуска и никогда не запускает такую сверку.
Неполный, ошибочный, старый или параллельный запуск бухгалтерские данные не удаляет.

Число в сообщении после ручного запуска теперь подписано как **«Подготовлено записей»**.
Это количество строк, сформированных 1С до нормализации и сопоставления в HUB, а не
подтверждение, что все строки уже привязаны к проектам.

Распроведенные документы и платежи, объекты с пометкой удаления, а также входящие платежи
с `Оплачено = Ложь` не пропадают из следующего обмена: расширение отправляет их с
`status = cancelled`. HUB сохраняет отмененный статус документов, а ранее импортированные
распределения этого платежного документа удаляет из фактических оплат проекта. При первом
обмене после обновления HUB также удаляет старые идентификаторы вида `GUID-НомерСтроки`.
Ручные оплаты HUB и записи другой базы 1С при этом не затрагиваются.
